# Plan d'implémentation — sujeedesign.com (site vitrine dynamique + back office)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer le site statique sujeedesign.com par une application FastAPI qui rend les pages publiques côté serveur (URLs propres, sans `.html`), expose un back office d'édition de contenu et reçoit les messages du formulaire de contact.

**Architecture:** FastAPI + SQLite (stdlib) + Jinja2. Tout contenu vit en base (`site.db` sur volume `/data`), les gabarits et le CSS vivent dans le dépôt. Une page est une suite ordonnée de sections typées ; réalisations et services sont des pages typées avec des métadonnées de listing. Aucun couplage avec crmsjd.

**Tech Stack:** Python 3.13, FastAPI, Uvicorn, Jinja2, SQLite (sqlite3), Pillow (optionnel pour les variantes d'images), pytest.

**Spec:** `docs/superpowers/specs/2026-10-17-site-cms-design.md`

## Global Constraints

- Dépôt : `github.com/Sujeedesign/sujeedesign-site` (public), branche `main`, aucun secret dans le code.
- URLs publiques sans extension : `/`, `/realisations`, `/realisations/<slug>`, `/services`, `/services/<slug>`, `/contact`, `/a-propos`, `/mentions-legales`, `/<slug>`.
- Redirections 301 : table de l'annexe du spec, exhaustive, sans exception.
- Direction artistique inchangée : `theme/assets/site.css` repris tel quel, classes existantes réutilisées, footer en `<h3>`, hiérarchie de titres séquentielle.
- Textes existants conservés mot pour mot (migration), sauf correction d'orthographe nécessaire.
- Secrets par variables d'environnement : `ADMIN_PASSWORD`, `SESSION_SECRET`, `SYNC_TOKEN`, `TOTP_SECRET` (optionnel).
- Volume persistant monté sur `/data` ; base `site.db`, médias `/data/medias`.
- Accessibilité : contraste AA, focus visible, lien d'évitement, `prefers-reduced-motion`, cibles 44 px, pas de débordement horizontal en 375/768/1024/1440 px.
- Le JavaScript des gabarits partagés vit dans `theme/assets/site.js`, jamais inline dans les gabarits.
- Tests exécutés avec `python3 -m pytest -q` depuis la racine du dépôt, base de test temporaire.

## Review Focus

- Contenu HTML collé par Sujee dans un champ riche : doit être nettoyé (balises autorisées uniquement), jamais rendu brut.
- Slug inexistant, slug renommé, slug en double : 404 propre, unicité garantie, aucune page fantôme ni écrasement.
- Publication d'une page avec section incomplète (champ vide, image sans alt) : la page ne doit jamais planter, le rendu doit rester valide et signaler l'incomplet dans le back office.
- Soumission du formulaire : double soumission, champs vides, email invalide, lien spam, soumission trop rapide (piège) doivent produire une réponse compréhensible sans jamais écrire de message fantôme.
- Publication concurrente pendant une requête publique : le cache doit se rafraîchir sans servir une page à moitié rendue ni une exception.
