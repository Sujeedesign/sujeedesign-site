# Recette du 17 octobre 2026 — nouveau site sujeedesign.com

Contrôle de la refonte (FastAPI + SQLite + back office) avant bascule en
production. Tout ce qui suit a été exécuté sur l'instance de recette
(`sujeedesign-site-staging`), jamais supposé.

## Ce qui est prouvé, et par quoi

| Contrôle | Moyen | Résultat |
|---|---|---|
| Logique applicative | `pytest -m "not e2e"` | 153 tests verts |
| Chaîne complète (proxy, cookies, redirections, cache de rendu, publication) | `pytest -m e2e` sur la recette (`SITE_E2E_URL`) | 4 tests verts |
| Parcours public réel | navigateur, clics réels | CTA, ancre `#travaux`, vignette, retour de fiche, envoi du formulaire (référence `MSG-…`) |
| Erreurs du formulaire | navigateur, envoi vide | une erreur par champ + statut global « Merci de corriger les champs signalés » |
| Écrans du back office | session HTTP réelle | tableau de bord, pages, éditeur, médias, messages, réglages, sauvegarde, aperçu : 200 |
| Export de sauvegarde | `/api/admin/export` | 200, 71 ko, 16 pages |
| Accessibilité clavier | navigateur | premier `Tab` = lien d'évitement ; menu mobile : `aria-expanded`, piège de focus, `Échap` rend le focus à l'ouvreur |
| Mouvement réduit | navigateur, `prefers-reduced-motion: reduce` | aucune animation jouée (durée ramenée à 0,01 ms, une seule itération), aucun contenu masqué |
| Sans JavaScript | `noscript` + `site-noscript.css` | titre et sections restent visibles |
| Débordement horizontal | navigateur, 6 pages × 375/768/1024/1440 | aucun, sur aucune page (`scrollWidth` = largeur utile) |

## Les trois points bloquants de la revue visuelle

1. **Vignette au premier écran (accueil, réalisations)** — la liste des
   réalisations montre sa première vignette à 640 px (375), 568 px (768),
   597 px (1024) et 747 px (1440) : visible sans défilement à toutes les
   largeurs. Sur l'accueil, le premier projet est atteint par le CTA
   « Découvrir les réalisations », qui défile jusqu'à `#travaux` (section
   ramenée à 66 px du haut) : c'est le parti pris du hero plein écran, il est
   désormais explicite et fonctionnel.
2. **Zone vide sous l'introduction des services sur mobile** — la première
   prestation commence à 530 px (375 × 667), dans le premier écran.
3. **Cadre noir de remplacement sur les fiches** — supprimé : sans photo
   fournie, le visuel d'ambiance reste seul, et le champ `image` du back office
   prend le relais dès qu'une vraie photo existe.

## Corrigé pendant cette passe

- **Accueil sur écrans courts** : à 375 × 667 le hero mesurait 815 px et
  poussait les deux actions sous la ligne de flottaison. Le portrait est
  maintenant plafonné par la hauteur (`30svh`) et le rythme vertical resserré :
  le hero fait exactement la hauteur de l'écran à 320 × 568, 360 × 640,
  375 × 667, 390 × 844 et 414 × 896.
- **Repli sans JavaScript** : `.hu`, `.reveal` et `.mw` partent à opacité nulle
  et n'étaient révélés que par script. Une feuille `site-noscript.css`, chargée
  uniquement dans `<noscript>`, garantit un contenu lisible. C'est la cause
  probable du hero « vide » observé sur certaines captures.

## Bascule en production (17 octobre 2026)

L'application Coolify `sujeedesign` a été reconfigurée pour construire ce dépôt
(Dockerfile, port 8080, healthcheck `/api/health`) et déployée sur
`sujeedesign.com`. Contrôles exécutés après la bascule, sur la production :

| Contrôle | Résultat |
|---|---|
| `/api/health` | 200, `{"ok":true,"version":"1.0.0"}` |
| Pages publiques (`/`, `/realisations`, `/services`, `/a-propos`, `/contact`, `/mentions-legales`) | 200 |
| 9 anciennes URL (`/identite.html`, `/projet-vaasam.html`, …) | 301 vers la bonne page |
| `www` et `http` | 200 et 302 vers `https://sujeedesign.com` |
| En-têtes | HSTS, `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy` |
| Back office | connexion 303, sept écrans 200, export 200 (72 ko, 16 pages) |
| Parcours de bout en bout complet (`pytest -m e2e` sur la production) | 4 tests verts |
| Formulaire public → base → notification Telegram | message enregistré (`MSG-00002`), 2 notifications envoyées, horodatage en base |
| Volume persistant | message et révision conservés après un redéploiement complet |

Les deux messages de recette ont été classés en spam dans le back office avec
une note explicite. La configuration d'origine de l'application est conservée
dans `/opt/data/site-rollback-sujeedesign.json` pour un retour immédiat à
l'ancien site statique.

## Ce qui reste, et qui n'est pas un défaut de code

- **Photos des réalisations** : les fiches attendent les vrais visuels, à
  déposer depuis le back office (champ `image`).
- **Contenus éditoriaux** : relecture finale par Sujee dans le back office,
  page par page.
- **En-têtes au niveau du proxy** : HSTS est posé par Traefik ; une éventuelle
  `Content-Security-Policy` reste à définir si on veut la durcir.
- **Recette** : l'application `sujeedesign-site-staging` garde son rôle de
  pré-production (volume persistant ajouté, elle perdait son contenu à chaque
  déploiement).

## Commandes de contrôle

```sh
# suite ordinaire
.venv/bin/python -m pytest -q -m "not e2e"

# parcours de bout en bout sur une instance vivante
set -a; . /opt/data/site-secrets.env; set +a
SITE_E2E_URL=http://<instance> SITE_E2E_PASSWORD="$SITE_ADMIN_PASSWORD" \
SITE_E2E_SYNC_TOKEN="$SITE_SYNC_TOKEN" .venv/bin/python -m pytest -q -m e2e
```
